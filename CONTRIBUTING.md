# Contributing to DWELL

Contributions must preserve the range's central contract: every promised piece
of telemetry is generated by a reproducible scenario action and is validated
against Elasticsearch.

## Scenario changes

1. Copy `scenarios/scenario_template.yml`; make `id` match the filename.
2. Add exactly three spoiler-safe `hints` (nudge, pivot, near-answer).
3. Implement the action in `attacks/runner.py` if it does not already exist.
4. Add detection queries grounded in observed telemetry—not assumed field names.
5. Run the offline check and then the live detection gate.

```bash
python3 scripts/validate_scenarios.py
./lab.sh validate scenarios/scenario_NN.yml
./lab.sh validate-detections
```

Do not commit learner submissions, credentials, packet captures, or an answer
that changes a public briefing into a spoiler.

## Pull requests

Run the source checks used in CI before opening a PR:

```bash
yamllint .
ruff check attacks scripts noise
shellcheck --severity=warning install.sh lab.sh attacks/seed.sh scripts/*.sh victim/linux/*.sh
docker compose -f docker-compose.yml -f docker-compose.linux-victim.yml config --quiet
```

The live integration workflow requires a self-hosted runner labelled
`DWELL-integration` with at least 16 GB RAM, Docker, and enough disk for the
range. It is manual because hosted GitHub runners do not meet the range's memory
budget reliably.
